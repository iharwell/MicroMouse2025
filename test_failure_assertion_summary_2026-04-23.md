## Remaining Logical Failure Units

### 1. Oscillation pairing blowout unit

These 16 failures are generated by one macro and all call the same helper in `MazeMap/MazeMapTest/DriveBaseTest.cpp`.

What the assertions actually check:
- The simulated step-response audit metrics must all be finite.
- `blowoutDetected` must remain false.

In this helper, `blowoutDetected` becomes true if any of the following happens:
- The last significant transient error peak is more than `1.05x` the first significant peak.
- Steady-state saturation duty exceeds `0.15`.
- Steady-state estimator mean absolute error exceeds the signal-specific steady-error threshold.
- Steady-state truth mean absolute error exceeds the same threshold.

So this unit checks that the closed-loop step response remains bounded, does not progressively amplify, does not spend too much time saturated in steady state, and tracks both the estimator and plant truth within the allowed steady-state error bounds.

### 2. `WallSensorLedCalibrationMode_UsesPauseInsteadOfAdvancingLoopTicks`

File: `MazeMap/MazeMapTest/ApplicationTest.cpp`

What the assertions actually check:
- The mode starts successfully.
- While waiting on the first hardware condition, the mode thread is still running.
- The control-loop session stays active.
- The loop diagnostic sequence has already advanced to a nonzero value.
- After switching into the next waiting phase, the mode thread is still running.
- The control-loop session is still active.

- The mode eventually exits cleanly.
- After exit, the control-loop session is inactive.

So this test checks that the mode pauses while waiting instead of consuming new loop ticks, and that it leaves the LED outputs cleaned up on exit.

### 5. `SrUkfCorePivotScrubModeMasksEncoderYawAndAppliesSoftZeroU`

File: `MazeMap/MazeMapTest/SrUkfCoreModeAndDiagnosticsTest.cpp`

What the assertions actually check:
- A pivot conflict can be seeded while pivot-scrub mode is still off.
- On the conflict tick, predict, encoder update, and yaw update all succeed.
- Pivot-scrub mode then engages.
- The encoder body update is skipped.
- soft-zero-`u` is applied.
- The masked encoder delta norm is finite and positive.
- Encoder-contributed `deltaPsi` and `deltaR` are forced to zero.
- Encoder wheel-speed deltas remain nonzero.
- Gyro yaw/rate/bias deltas remain finite or nonzero as expected.

- The zero-`u` innovation and applied delta are nonzero.
- Debug dump lines for pivot scrub, encoder masking, zero-`u`, and gyro masking are all present.

So this test checks the full pivot-scrub masking contract: when encoder and gyro yaw evidence conflict during an in-place pivot, the estimator must suppress encoder body-yaw influence, preserve wheel evidence, apply a soft zero-forward-velocity correction, and emit the corresponding diagnostics.

### 10. `SrUkfCoreDoesNotLetControlInputCreateUnboundedForwardMotionWithEncoderOpposition`

File: `MazeMap/MazeMapTest/SrUkfCoreMotionUpdateTest.cpp`

What the assertions actually check after 200 cycles of positive drive command with zero encoder and zero yaw observations:

- Encoder and yaw updates are both attempted and accepted every cycle.
